# Hayumeri

Начальная веб-версия проекта на TypeScript и Vite для локального запуска в Windows.

## Двойной щелчок для запуска

1. Скачайте и распакуйте **весь репозиторий**, включая `scripts/` и `src/`, в любую доступную для записи папку на внутреннем или внешнем SSD.
2. Откройте `Hayumeri.bat` двойным щелчком. **Права администратора не нужны.**
3. При первом запуске понадобится интернет для установки npm-зависимостей. Если подходящего Node.js с npm нет, программа скачает портативный Node.js **24.22.2 LTS** с `nodejs.org` и проверит SHA-256 архива.
4. Запуск проверит свободный порт, дождётся HTTP-ответа и лишь после этого откроет браузер. Фактический URL выводится в консоль и сохраняется в `.runtime/launcher-status.json`.
5. Для завершения работы нажмите `Ctrl+C` в окне BAT. Повторное нажатие BAT, пока первый сервер работает, **не создаст второй сервер**.

Допустимы пути с пробелами, кириллицей и `!`. Скрипт использует `pushd` для UNC-путей. Папка должна быть доступна для записи; запуск напрямую из ZIP-архива не поддерживается.

## Диагностика

- `logs/launch.log` — сообщения подготовки и запуска. Вывод Vite находится в `logs/vite-*.out.log` и `logs/vite-*.err.log`. После достижения 4 МБ прежний файл переносится в `logs/launch.previous.log` при новом запуске.
- `.runtime/` — портативный Node.js, npm-кэш, метаданные установки; эти файлы **локальные** и не публикуются в GitHub.
- `node_modules/` — npm-зависимости. Устанавливаются при первом запуске, изменении контрольных данных либо отсутствии проверяемых файлов пакетов.
- `config/launcher.json` — порт и диапазон, таймаут проверки HTTP, максимум 1–3 попытки и открытие браузера. Неверная конфигурация отклоняется до запуска сервера.
- `config/integrity.json` — проверочные SHA-256 исходников. Изменённый файл блокирует запуск; код не перезаписывается автоматически. Манифест не имеет цифровой подписи и защищает от случайной порчи, а не от целенаправленной подмены.
- `.runtime/launcher-status.json` — машинно-читаемые состояния `ПРОВЕРКА`, `ВОССТАНОВЛЕНИЕ`, `ЗАПУСК`, `РАБОТАЕТ`, `ОШИБКА`, `ОСТАНОВЛЕНО`.
- `.runtime/launch-metrics.json` — замеры этапов подготовки, проверки и общего времени до готовности.
- При ошибке окно BAT остаётся открытым с кодом выхода. Если Node.js не скачивается, проверьте доступ к `nodejs.org`; если npm не устанавливает зависимости — доступ к реестру npm и свободное место.
- На повторном запуске, пока первый сервер работает, второй BAT сообщит об этом и завершится без остановки первого.
- Скрипт не изменяет системные настройки, не требует Python и не завершает чужие процессы.

## Разработка

```bash
npm install
npm test
npm run build
npm run dev
```

Автоматическая проверка Windows в `.github/workflows/windows-launch.yml` выполняет тесты, сборку, проверку BAT в пути с кириллицей и спецсимволами, занятый порт, контроль статуса и отрицательные тесты повреждённых файлов/настроек.

**Состояние:** пока это стартовый каркас. Основной сайт уже имеет локальную систему обновления из GitHub, но прочие функциональные модули и долгие нагрузочные тесты ещё не реализованы.

## Поведение при ошибках

Система ограничивает количество попыток запуска (`maxAttempts`), проверяет HTTP и показывает ошибку на русском языке. Если повреждены npm-зависимости, они восстанавливаются из npm при наличии интернета; документы и настройки при этом не удаляются. Если повреждены исходники приложения, запуск останавливается: для восстановления требуется доверенный архив. Для обновления исходников сайта теперь предусмотрен значок GitHub в шапке с локальным резервированием и откатом; ручное восстановление может понадобиться после принудительного выключения ПК посреди копирования.

## Управление и персонализация интерфейса

- Кнопка **☰** или `Ctrl+B` сворачивает/разворачивает боковую панель на мониторах с доступной шириной более 930 CSS-пикселей.
- Боковую панель и список заметок можно изменять по ширине мышью (или стрелками при фокусе на разделителе).
- **☆** рядом с разделом закрепляет его выше обычных пунктов. Закрепление не меняет данные в разделах.
- **Ctrl+K** или кнопка поиска в шапке открывают палитру команд: переходы по разделам, настройки, обновления и управление меню. **Это поиск команд и разделов, а не полнотекстовый поиск по заметкам.**
- **Ctrl+,** открывает настройки; **Ctrl+S** сохраняет текущую заметку в редакторе.
- Настройки позволяют менять размер текста (90–130%), плотность элементов, ширину бокового меню (206–340 px), ширину редактора (760–1600 px), соотношение списка заметок (25–52%), эффекты, свёрнутое меню. Мобильная компоновка имеет приоритет над ручной шириной меню.
- Предпочтения сохраняются в **`.runtime/ui-preferences.json`** и восстанавливаются при запуске, даже если Vite выбирает другой локальный порт. Предыдущая успешная версия файла сохраняется в `.runtime/ui-preferences.previous.json`.

Не удаляйте `.runtime` при ручном обновлении. Для настроек действует проверка структуры, резервное копирование и контроль ревизий: одновременные изменения из другой вкладки отклоняются, а не перезаписываются молча. Содержимое заметок и задач остаётся отдельно в `.runtime/workspace-data.json`. Если запись настроек не удалась, интерфейс сообщает об ошибке.

## Адаптация под мониторы

Сайт автоматически использует размер **области браузера в CSS-пикселях**, поэтому перестраивается при переносе окна между мониторами, изменении размера окна, масштаба браузера и Windows:

- **Небольшие ноутбуки (окна ~931–1399 px)** — компактное боковое меню, главная страница без тесных двух колонок.
- **Full HD / 2K (окна от ~1400 px)** — расширенная рабочая область с боковой навигацией и ограниченной длиной строк.
- **4K и широкоформатные экраны (от ~1850/2560 CSS px)** — больше полезной площади, но заметки, задачи и тексты не растягиваются на всю ширину.
- **Узкие окна и высокий масштаб (до 930 px)** — горизонтальная прокручиваемая навигация; редактор перестраивается в одну колонку до 760 px.
- **Низкие/широкие окна** — главная страница и редактор уменьшают вертикальные поля, остаются прокручиваемыми.

Для адаптации не требуются системные разрешения, JavaScript-детекторы физического монитора или дополнительный 3D-движок. Внешний вид зависит от **эффективного пространства окна**, а не от обозначения «4K» в характеристиках дисплея. Браузер с масштабом 200% на 4K может использовать компоновку обычного Full HD.

В Windows GitHub Actions запускается браузер Edge/Chrome и проверяются 13 размеров от **320×640 до 3840×2160** с разными значениями devicePixelRatio, включая главную страницу, заметки и задачи. Это проверка браузерного расположения и отсутствия горизонтального переполнения; она не заменяет визуальную проверку на конкретной модели дисплея.

## Рабочие пространства

Главная страница и все разделы объединены чёрно-золотой навигацией: «Заметки», «Задачи», «Знания», «Память», «Граф», «Агенты», «Чат», «Диск» и «Система».

**Заметки и задачи работают локально** и сохраняются в `.runtime/workspace-data.json` рядом с установленной Hayumeri — независимо от выбранного порта. При изменениях сохраняется предыдущая копия, доступная в `.runtime/workspace-data.previous.json`. **Заметки сохраняются по кнопке, не автоматически.** Другие разделы пока содержат подготовленный интерфейс и честные указания «Модуль не подключён», а не вымышленные данные.

Подробнее: [Рабочие пространства и ограничения](docs/workspaces.md).

## Четыре NoSQL-базы (отдельно от сайта)

В проект включены **MongoDB, Redis, Neo4j и Qdrant**, а также TypeScript-драйверы и проверки реального подключения. Для запуска четырёх сервисов требуется установленный и работающий Docker Desktop в режиме Linux-контейнеров. Первый запуск может потребовать загрузки крупных Docker-образов.

- `Hayumeri-DB.bat` или `Hayumeri-DB.bat start` — создать локальные пароли (при отсутствии) и запустить четыре базы.
- `Hayumeri-DB.bat check` — проверить их доступность и авторизацию.
- `Hayumeri-DB.bat status` — показать состояние контейнеров.
- `Hayumeri-DB.bat logs` — показать журналы.
- `Hayumeri-DB.bat stop` — остановить без удаления пользовательских данных.

**Важно:** обычный `Hayumeri.bat` продолжает работать без Docker. Пароли записываются в исключённый из Git `.env.nosql`. Данные Docker хранятся в именованных томах, а не автоматически на внешнем SSD. Подробности и ограничения: [docs/nosql.md](docs/nosql.md).

## Обновление приложения с сайта

Нажмите значок круговых стрелок **справа вверху**. В открывшемся окне можно проверить ветку `main` репозитория GitHub, посмотреть последнюю ревизию, описание изменения и установить обновление. Установщик скачивает точный коммит, проверяет Git-объекты, создаёт резервную копию, перезапускает BAT и проверяет HTTP-ответ. При сбое запуска автоматически пытается откатить обновление. Данные NoSQL, API-ключи и пользовательские папки не перезаписываются.

Установка работает при запуске **Hayumeri.bat** на Windows из обычной папки; при запуске через `npm run dev` интерфейс допускает только проверку. Для Git-клона применяйте `git pull`. Подробные инструкции и ограничения: [docs/updates.md](docs/updates.md).
