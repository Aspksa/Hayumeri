# Четыре NoSQL-базы Hayumeri

В проекте предусмотрены **MongoDB (документы), Redis (кэш), Neo4j (граф знаний) и Qdrant (векторы)**. Они изолированы от браузера и основного BAT-запуска. Подключение из TypeScript выполняется только на стороне сервера, в `server/src/databases.ts`.

## Требования и первый запуск

Для всех четырёх сервисов нужен **Docker Desktop с Linux-контейнерами и Docker Compose v2**. На Windows для установки Docker Desktop, WSL 2 и первоначальной настройки могут понадобиться права администратора. Сам `Hayumeri-DB.bat` их не запрашивает. Установка Docker не выполняется автоматически.

1. Установите и запустите Docker Desktop, дождитесь готовности Docker Engine.
2. Из папки проекта выполните двойным нажатием `Hayumeri-DB.bat` или `Hayumeri-DB.bat start`.
3. При первом запуске создаётся **`.env.nosql`** с четырьмя 64-символьными случайными паролями. Этот файл исключён из GitHub. Не передавайте его другим людям.
4. Docker загрузит четыре контейнера. Neo4j обычно стартует дольше остальных.
5. Для проверки выполните `Hayumeri-DB.bat check`; для просмотра состояния — `Hayumeri-DB.bat status`; для просмотра последних журналов — `Hayumeri-DB.bat logs`.

Для остановки без удаления данных: `Hayumeri-DB.bat stop`. **Не используйте `docker compose down -v` — он удалит тома с данными.** При повторном запуске пароли сохраняются. Не удаляйте `.env.nosql` при существующих базах: изменение паролей не сбрасывает пароль внутри уже созданной MongoDB или Neo4j.

Обычный `Hayumeri.bat` по-прежнему запускает сайт отдельно; наличие Docker для сайта не обязательно.

## Локальные адреса

| База | Локальный адрес | Назначение |
|---|---|---|
| MongoDB | `127.0.0.1:27017` | Чаты, память, заметки, агенты |
| Redis | `127.0.0.1:6379` | Кэш, очереди, временные состояния |
| Neo4j | `bolt://127.0.0.1:7687`, браузер `http://127.0.0.1:7474` | Граф знаний и связи |
| Qdrant | `http://127.0.0.1:6333` | Векторный поиск и эмбеддинги |

Все открытые порты привязаны к `127.0.0.1`; пароли обязательны. API Qdrant использует HTTP с ключом только на localhost — **не публикуйте порт 6333 в сеть** без HTTPS/TLS и отдельной настройки безопасности.

## Подключение TypeScript

Серверные зависимости устанавливаются отдельно, чтобы не нагружать обычный запуск сайта:

```powershell
npm install --prefix server
npm --prefix server run check:types
npm --prefix server run db:check
npm --prefix server run db:smoke
```

`db:check` проверяет авторизацию всех четырёх баз и возвращает код ошибки при недоступности хотя бы одной. `db:smoke` создаёт временные тестовые данные, читает и удаляет их в четырёх базах. Это не миграция пользовательских данных. Программные адаптеры находятся в `server/src/databases.ts`; никакие пароли не включаются в веб-сборку.

## Данные и ресурсы

Docker хранит данные в **именованных томах** (`mongodb_data`, `redis_data`, `neo4j_data`, `qdrant_data`). Они переживают `stop` и перезапуск контейнеров. Однако **по умолчанию Docker хранит тома в своём хранилище, а не рядом с BAT на внешнем SSD**. Если требуется переносить данные с диском M.2, нужно отдельно настроить расположение Docker-хранилища и процедуру резервного копирования.

Четыре сервиса потребляют существенно больше ресурсов, чем один веб-сервер. В Compose заданы ограничения памяти примерно до 1 ГБ для MongoDB, 256 МБ Redis, 1,6 ГБ Neo4j и 1 ГБ Qdrant, плюс расходы Docker/WSL. Для ноутбука с 16 ГБ RAM запускайте сервисы только при необходимости; их работа не обязательна для сайта.

**Ограничения:** стек подготовлен в репозитории, но физическая установка Docker на компьютере и миграция существующих пользовательских данных не выполняются удалённо. Коннекторы готовы для серверного кода, однако текущая веб-страница Hayumeri пока остаётся начальным каркасом и не использует базы автоматически. Для реальных данных потребуется резервное копирование и прикладная схема хранения.
