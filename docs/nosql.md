# Четыре NoSQL-базы Hayumeri

В проекте предусмотрены **MongoDB (документы), Redis (кэш), Neo4j (граф знаний) и Qdrant (векторы)**. Они изолированы от браузера. При старте обычного `Hayumeri.bat` отдельный фоновый менеджер автоматически пытается подготовить Docker и базы; сам сайт не ждёт завершения Docker. Подключение из TypeScript выполняется только на стороне сервера, в `server/src/databases.ts`.

## Автоматический запуск — команды запоминать не нужно

**Открывайте обычный `Hayumeri.bat`:** приложение откроет сайт сразу, а отдельный фоновой менеджер начнёт запуск MongoDB, Redis, Neo4j и Qdrant. Вкладка **«Система»** показывает фактическое состояние, включая количество запущенных контейнеров, текущий профиль RAM и доступный объём диска. Проверка автоматически повторяется приблизительно раз в 2,5 минуты; отображение обновляется каждые 30 секунд.

Один раз необходимо установить и первично настроить **Docker Desktop (WSL 2, Linux-контейнеры, Docker Compose v2)**. При установке Docker могут потребоваться права администратора. Hayumeri не устанавливает Docker самостоятельно, не повышает привилегии и не обещает устранить ошибки первого запуска Docker.

Если Docker уже установлен, менеджер при необходимости пытается открыть Docker Desktop и после готовности движка запускает четыре контейнера с теми же именованными томами. Первый запуск может долго скачивать образы. Если Docker отсутствует/не готов, сайт, заметки, задачи и обновления остаются доступны, а в разделе «Система» показывается причина.

**Ресурсы и безопасность:** на ноутбуке с 16 ГБ RAM выбирается профиль `balanced` (сумма максимальных лимитов контейнеров 6 ГиБ). Только если Docker и Windows имеют существенный запас памяти, и загрузка контейнера держится выше 85% **три проверки подряд**, менеджер может включить `growth`. Если RAM не хватает, он остаётся на более безопасном режиме; лимит не снимается бесконтрольно. Если пользователь ранее вручную установил профиль, автоматика его не переопределяет. При недостатке свободного места новые запуски приостанавливаются. При исчезновении `.env.nosql` при существующих томах автоматика **не создаёт новые пароли**: восстановите исходный файл, иначе старые базы могут стать недоступными.

Состояние записывается в `.runtime/nosql-auto-status.json`; технический журнал в `.runtime/nosql-auto.log`. Журналы запуска Docker — `.runtime/nosql-auto-command.out.log` и `.runtime/nosql-auto-command.err.log`. Пароли хранятся отдельно в `.env.nosql` и не выдаются через API. При закрытии Hayumeri фоновый менеджер заканчивает работу, но **не останавливает контейнеры**: другие программы могут продолжать пользоваться ими. Для экономии памяти на неработающем ПК Docker Desktop можно выключать вручную.

Текущий статус контейнера не означает автоматически, что пароль и запросы к базе проверены. В CI действительно запускаются все четыре Docker-движка и отдельно тестируются подключение и операции с данными; на вашем компьютере такой тест ещё не выполнен.

## Дополнительные команды для диагностики (необязательны)

`Hayumeri-DB.bat check` проверяет авторизацию всех четырёх баз; `Hayumeri-DB.bat stats` показывает фактическую RAM/CPU; `Hayumeri-DB.bat stop` останавливает контейнеры **без удаления томов**. Если хотите вручную выбрать профиль, доступны `balanced` и `growth`.

Первый запуск создаёт `.env.nosql` с четырьмя секретами, если файл отсутствует и томов ещё нет. Не передавайте секреты в GitHub; **никогда не используйте `docker compose down -v`** с рабочими данными.

## Локальные адреса

| База | Локальный адрес | Назначение |
|---|---|---|
| MongoDB | `127.0.0.1:27017` | Чаты, память, заметки, агенты |
| Redis | `127.0.0.1:6379` | Кэш, очереди, временные состояния |
| Neo4j | `bolt://127.0.0.1:7687`, браузер `http://127.0.0.1:7474` | Граф знаний и связи |
| Qdrant | `http://127.0.0.1:6333` | Векторный поиск и эмбеддинги |

Все открытые порты привязаны к `127.0.0.1`; пароли обязательны. API Qdrant использует HTTP с ключом только на localhost — **не публикуйте порт 6333 в сеть** без HTTPS/TLS и отдельной настройки безопасности.

## Подключение TypeScript

Серверные зависимости устанавливаются отдельно, чтобы не нагружать обычный запуск сайта:

```powershell
npm install --prefix server
npm --prefix server run check:types
npm --prefix server run db:check
npm --prefix server run db:smoke
```

`db:check` проверяет авторизацию всех четырёх баз и возвращает код ошибки при недоступности хотя бы одной. `db:smoke` создаёт временные тестовые данные, читает и удаляет их в четырёх базах. Это не миграция пользовательских данных. Программные адаптеры находятся в `server/src/databases.ts`; никакие пароли не включаются в веб-сборку.

## Данные и ресурсы

Docker хранит данные в **именованных томах** (`mongodb_data`, `redis_data`, `neo4j_data`, `qdrant_data`). Они переживают `stop` и перезапуск контейнеров. Однако **по умолчанию Docker хранит тома в своём хранилище, а не рядом с BAT на внешнем SSD**. Если требуется переносить данные с диском M.2, нужно отдельно настроить расположение Docker-хранилища и процедуру резервного копирования.

### Профили ресурсов

Вместо прежних жёстких лимитов введены **сбалансированный** (по умолчанию) и **усиленный** профили. Оба предназначены для локальной работы без неконтролируемого потребления ОЗУ. Для выбора используйте отдельный BAT — существующий `Hayumeri.bat` не запускает Docker.

| Сервис | balanced: потолок контейнера | growth: потолок контейнера |
|---|---:|---:|
| MongoDB | 1536 МиБ, кэш 512 МиБ | 2048 МиБ, кэш 768 МиБ |
| Redis | 512 МиБ, данные 256 МБ | 640 МиБ, данные 384 МБ |
| Neo4j | 2048 МиБ, heap 768 МиБ + page cache 512 МиБ | 2560 МиБ, heap 1024 МиБ + page cache 768 МиБ |
| Qdrant | 2048 МиБ | 2560 МиБ |
| **Сумма лимитов контейнеров** | **6144 МиБ (6 ГиБ)** | **7808 МиБ (≈7,6 ГиБ)** |

Память Docker Engine/WSL, буферы хранения и прочие процессы требуют дополнительной RAM. Значения в таблице — максимумы, а **не постоянно зарезервированный расход**. На ноутбуке с 16 ГБ оперативной памяти начните с `balanced`. Для `growth` скрипт проверяет не менее **9 ГиБ памяти, видимой Docker Engine**, и откажет с понятной ошибкой, если Docker/WSL ограничен сильнее. Это не гарантирует, что хосту всегда хватит RAM: следите за другими программами.

Команды:

```bat
Hayumeri-DB.bat resources
Hayumeri-DB.bat start
Hayumeri-DB.bat stats
Hayumeri-DB.bat growth
Hayumeri-DB.bat check
Hayumeri-DB.bat balanced
```

- `resources` показывает выбранный профиль **без запуска Docker**.
- `stats` показывает реальное потребление RAM/CPU работающими контейнерами (нужен Docker).
- `growth` повышает лимиты при достаточной памяти Docker, выполняет `docker compose up -d` и **только при успехе** запоминает профиль в `.runtime/nosql-profile.json`. Возможен перезапуск контейнеров; перед переключением с важными данными сделайте резервную копию.
- `balanced` возвращает более экономичные значения без удаления томов; если текущие данные требуют больше RAM, снижение лимита может вызвать проблемы — проверьте `stats` заранее.
- `start` использует последний успешно выбранный профиль. При повреждении файла профиля система останавливается с ошибкой, не сбрасывая настройки и данные автоматически.

**Redis:** включён AOF, а политика `noeviction` вместо `allkeys-lru`: при исчерпании памяти Redis **отклонит новую запись**, а не будет автоматически выталкивать ключи. Это предотвращает незаметную потерю состояния, но не делает Redis безлимитным и не заменяет надёжное хранение долговременной памяти в MongoDB/Neo4j. При заполнении памяти увеличьте профиль, устраните причину роста или удалите только явно устаревший кэш.

**Данные могут расти на диске:** именованные тома сохраняются при смене профилей и после `stop`, квоты по размеру базы не установлены. По мере роста графа и векторного индекса потребуются контроль свободного места и резервные копии. Для действительно крупных коллекций Qdrant необходима отдельная настройка `on_disk`/memmap при создании коллекций; поднятие RAM само по себе не заменяет дисковые векторы. Отключение лимитов полностью на 16 ГБ ноутбуке не рекомендуется.


**Ограничения:** стек подготовлен в репозитории, но физическая установка Docker на компьютере и миграция существующих пользовательских данных не выполняются удалённо. Коннекторы готовы для серверного кода, однако текущая веб-страница Hayumeri пока остаётся начальным каркасом и не использует базы автоматически. Для реальных данных потребуется резервное копирование и прикладная схема хранения.
